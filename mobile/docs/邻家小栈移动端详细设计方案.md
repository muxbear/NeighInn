## 1. 方案概述

### 1.1 编写目的

本文档以当前 Figma Make 原型为**视觉与交互唯一基准**，结合《邻里小栈需求规格说明 v1.1》《移动端概要设计 v1.0》《UI/UX 设计规范 v1.0》，给出移动端可落地的详细设计方案，覆盖：

- 多端技术方案：uni-app x 蒸汽模式，一套代码交付 Android / iOS / HarmonyOS / 微信小程序；
- Figma 设计还原：布局、样式、配色、字体字号、图标、图片、动效、交互的逐项落地规则；
- 工程结构、组件库、页面级规格、数据模型、接口契约、状态管理；
- 交易、认证、IM、支付、AI 质检等 Figma 未覆盖页面的补齐方案；
- 多端差异、性能、安全、无障碍、测试与验收。

预期读者：移动端开发工程师、UI/UX 设计师、前端架构师、测试工程师、产品经理。

### 1.2 设计来源与优先级

当资料之间出现冲突时，按以下顺序裁决：

| 优先级 | 资料 | 适用范围 |
| :-: | --- | --- |
| 1 | **Figma Make 原型**（当前最新） | 移动端布局、样式、配色、字体字号、图标、文案、交互、页面结构 |
| 2 | 《需求规格说明 v1.1》 | 业务规则、权限、数据、交易与资金规则、验收标准 |
| 3 | 《移动端概要设计 v1.0》 | 技术架构、模块划分、接口契约、状态管理、缓存 |
| 4 | 《UI/UX 设计规范 v1.0》 | Figma 未覆盖页面的组件与视觉基线；Figma 已覆盖部分以 Figma 为准 |

> **重要说明**：Figma Make 是 React + Tailwind 的可交互原型，其源码中的 CSS 只能作为**尺寸、颜色、字号、交互的参考值**，不能直接复制到 uni-app x。第 3.6 节给出完整的 ucss 适配规则。

### 1.3 设计基准

| 项目 | 值 |
| --- | --- |
| 设计画布 | 430 × 932（Figma Make 运行时 `phone-shell` 宽度 430px，iPhone 14 Pro Max 逻辑尺寸） |
| 状态栏 | 设计稿 30px；真机使用系统实际状态栏高度，保留下方内容间距关系 |
| 页面左右边距 | 14px（首页信息流/专属区/生活频道）、16px（首页头部/分类栏）、17px（详情卡片）、20px（登录） |
| 底部 TabBar | 78px（含 7px 上内边距 + 安全区） |
| 页面底部预留 | 92px（TabBar 场景）、76–82px（详情/发布固定操作栏场景） |
| 字体 | 系统字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif` |
| 字号范围 | 6px–29px（Figma 原值，详见 4.3；存在可读性风险，见 13.2 R-01） |
| 布局模型 | Flex 为主；设计稿中的 Grid/Gap/伪元素需按第 3.6 节转换 |

### 1.4 方案目标

| 编号 | 目标 | 度量 |
| --- | --- | --- |
| G-01 | 多端一次开发 | 同一套 `.uvue` + TS 代码编译到 Android/iOS/HarmonyOS/微信小程序 |
| G-02 | Figma 严格还原 | 430×932 基准下布局偏差 ≤ 2px；颜色/字号/圆角/阴影使用设计原值 |
| G-03 | 交易闭环 | 货币担保、免费赠与、物品互换三种方式全流程可用 |
| G-04 | 性能 | 首页首屏 ≤ 2s（4G）；列表滚动 ≥ 55fps（目标 60fps）；主包 ≤ 2MB（微信） |
| G-05 | 可用性 | 核心路径 ≤ 3 步；关键操作可二次确认；触控热区 ≥ 44×44 |
| G-06 | 安全 | 敏感信息不落明文；支付/认证/审核全链路可追溯 |

## 2. 与现有文档的差异及待确认事项

### 2.1 技术栈变更

| 维度 | 原文档（概要设计 v1.0） | 本方案 | 影响 |
| --- | --- | --- | --- |
| 框架 | uni-app（Vue 3 + TS） | **uni-app x（蒸汽模式 Vapor）** | 工程结构、CSS 子集、UTS 插件、构建方式均变化 |
| 页面后缀 | `.vue` | `.uvue` | 全部页面/组件需使用 uvue |

## 3. uni-app x 技术基线

### 3.1 为什么选择 uni-app x

| 维度 | 说明 |
| --- | --- |
| 一套代码多端 | 官方支持编译到 Android、iOS、HarmonyOS、Web、微信小程序、支付宝小程序 |
| 原生渲染 | App 端基于原生渲染管线，不是 WebView；滚动、长列表、图片性能优于 WebView 方案 |
| 蒸汽模式性能 | 官方 4050 view/text 测试中，Android 约为原生 View 的 2 倍、iOS 约为 UIKit 的 2 倍、HarmonyOS 约为 ArkUI 的 2.85 倍 |
| 开发体验 | Vue 3 组合式 API + TS/JS + CSS 子集，AI 友好；SCSS 可继续使用 |
| 生态 | 兼容 npm（Pinia、day.js 等纯 JS 库）；uni_modules + UTS 插件；uni-ui x 官方组件库 |
| 渐进升级 | VDOM 模式代码可通过 `uts2js` 运行在 Vapor；也可将 uni-app 老项目逐步迁移 |

### 3.2 运行模式：蒸汽模式（Vapor）与 VDOM

> 依据 uni-app x 官方文档（2026-11 更新）：HBuilderX 5.0+ 鸿蒙支持蒸汽模式，5.11+ iOS，5.21+ Android；5.25+ 新建项目默认蒸汽模式。

| 维度 | 蒸汽模式 Vapor（本方案采用） | VDOM 模式（兼容/回退） |
| --- | --- | --- |
| 渲染 | 去掉虚拟 DOM；template/style 编译为字节码/机器码 | 虚拟 DOM + 原生渲染 |
| 语言 | TS/JS（HBuilderX 5.31+ 可分别用 ts/js/uts） | UTS（强类型，编译为 Kotlin/Swift/ETS/JS） |
| 页面写法 | **仅组合式 API（`<script setup>`）**；不支持选项式、不支持 mixin | 组合式/选项式均可 |
| CSS | 只支持简单 class 选择器与分组选择器；不支持复杂关系选择器；仅样式隔离 2.0 | 支持更多选择器；兼容老写法 |
| 组件 | 不支持 uts 兼容模式组件；仅标准模式（native-view） | 兼容模式仍可用 |
| 列表 | `list-view` 全面复用；`list-item` 的 `v-for` 必须有 `:key`，且与 `list-view` 同文件 | 旧复用写法 |
| 轮播 | `swiper` 支持 indicator 插槽、3D；默认高度 150px | 旧行为 |
| 最低系统 | Android 6.0+ / iOS 15+ / HarmonyOS 6.0+（API 20+） | Android 5.0+；iOS 以兼容表实测为准（SRS 基线 iOS 13） |
| 小程序/Web | 编译为 VDOM 运行（后续升级，不影响使用） | VDOM |
| 热更新 | Android/iOS 支持 wgt（HBuilderX 5.31+）；HarmonyOS 暂不支持 | 支持 |
| 适用 | 新项目、追求性能、接受组合式 | 老项目、需 iOS 13/14、需复杂 CSS |

**结论**：新项目采用 Vapor；在 `manifest.json` 中开启：

```json
{
  "uni-app-x": {
    "vapor": true,
    "styleIsolationVersion": "2",
    "vapor-render-target": "bytecode",
    "vapor-default-script-lang": "ts"
  }
}
```

> `bytecode` 为默认视图层编译目标，编译速度与热更新更好；`nativecode` 性能略高但编译慢。鸿蒙可选两者之一。

### 3.6 ucss 限制与 Figma CSS 转换规则

这是本方案最关键的技术适配部分。Figma Make 使用 Web CSS（Grid、Gap、伪元素、复杂选择器），而 uni-app x App 端只支持 **Web CSS 子集（ucss）**。以下规则必须落到组件实现：

#### 3.6.1 基础规则

| 规则 | 说明 | 对 Figma 的影响 |
| --- | --- | --- |
| 仅 class 选择器 | 不支持 tag、`#id`、`[attr]`；Vapor 还不支持复杂关系选择器 | 所有 BEM 化；禁止 `.a .b`、`:has`、`:nth-child` |
| class 字符集 | 仅 `A-Z a-z 0-9 _ -` | Figma 中的中文类名（`.物品赠与`）必须改为英文 BEM（`.zone-card--gift`） |
| 样式不继承 | 文字样式必须写在 `<text>` 上 | 所有标题/正文/说明使用 `<text>`，不能依赖父级 `color/font-size` |
| 默认纵向 Flex | 全平台 `flex-direction: column` | 横向布局显式 `flex-direction: row` |
| 仅 Flex + 定位 | 不保证 Grid；布局用 Flex + absolute/fixed | `display:grid` 全部改 Flex |
| 无 `gap` | ucss 属性清单未包含 gap | 用 `margin` 或容器 `padding` 实现间距 |
| 无伪元素 | `::before/::after` 不可用 | 装饰圆、下划线、分割线用真实 `<view>` |
| 无 `:active` 依赖 | 用 `hover-class` 或状态类 | 按钮/卡片按压态用 `hover-class="is-pressed"` |
| 无 `-webkit-line-clamp` | 用 `<text :lines="2">` | 商品标题/描述两行截断 |
| 图片裁剪 | 用 `<image mode="aspectFill">` | 替代 `object-fit: cover` |
| 无 `aspect-ratio` | 用固定高度或 JS 计算 | 商品图/生活图/封面图 |
| CSS 变量 | `var()` 支持；不要依赖 `:root` | Token 以 SCSS 编译期变量为主，动态主题用内联 style/主题类 |
| `@media`/`@keyframes`/`calc`/`env` | 支持 | 360px 断点、动画、安全区 |
| `position: fixed/sticky` | 支持 | 底部操作栏、吸顶分类 |
| `z-index` | 仅同层兄弟节点 | 弹层结构需平级 |
| `!important` | 仅 class 选择器可用 | 尽量不用 |
| `backdrop-filter` | 支持但性能开销大 | 列表/长页面降级为半透明纯色 |

#### 3.6.2 Figma → ucss 逐项转换表

| Figma CSS 用法 | 出现位置 | ucss 替代方案 |
| --- | --- | --- |
| `display: grid; grid-template-columns: repeat(4,1fr)` | 专属区 4 卡、我的内容 4 格、统计 4 格、订单 3 格、通知 4 Tab | `flex-direction: row`；子项 `flex: 1` 或 `width: calc(...)` |
| `gap: 12px` | 商品网格、卡片列表、表单 | 子项 `margin-right`/`margin-bottom`；末项用 `:last-child`（仅 Web）或类名 `is-last`；推荐容器负 margin + 子项 margin |
| `aspect-ratio: 1 / 0.94` | 商品图 | 固定高度 `189px`（430 宽基准）或 JS 计算 `width * 0.94` |
| `aspect-ratio: 1.35` | 互换订单图 | 固定高度或 JS 计算 |
| `-webkit-line-clamp: 2` | 商品标题、动态摘要 | `<text :lines="2">` |
| `:has(.service-kind.offer)` | 服务卡片按钮变绿 | 在数据层计算 `isOffer`，渲染 `service-card--offer` 类 |
| `.zone-card.物品赠与` | 专属区配色 | `.zone-card--gift` / `.zone-card--swap` / `.zone-card--sale` / `.zone-card--service` |
| `::before/::after` 装饰圆/下划线/分割线 | 首页头部光晕、分类下划线、广播装饰圆、feed-end 线条 | 独立 `<view class="decor-circle">` / `<view class="tab-underline">` |
| `:active { transform: scale(.985) }` | 商品卡、通知卡 | `hover-class="card--pressed"` + `hover-stay-time="100"` |
| `backdrop-filter: blur(...)` | 底部栏、弹层、详情导航 | 半透明 `rgba` 背景；高端设备可 `backdrop-filter`（条件编译/配置开关） |
| `background: radial-gradient(...)` | 头部光晕、卡片光晕 | 优先线性渐变；不支持径向渐变时用半透明圆形 `<view>` 叠加或预渲染 PNG |
| `object-fit: cover` | 所有图片 | `<image mode="aspectFill">` |
| `font-variant-numeric: tabular-nums` | 价格/时间 | 不支持则忽略；保证数字字体一致 |
| `filter: saturate(.6)` | 已读通知图标 | 直接使用低饱和图标资源或 `opacity: .72` |
| `cursor: pointer` | Web 交互 | App 无意义；Web 条件编译保留 |

```

## 4. Figma 设计还原体系

### 4.1 还原原则

| 编号 | 原则 | 说明 |
| --- | --- | --- |
| RP-01 | **像素基准** | 以 430×932 为基准；所有尺寸取 Figma 原值，不使用 8pt 网格强行取整 |
| RP-02 | **不整体缩放** | 使用 `px` 而非 `rpx` 实现字号/圆角/边框，保证 430 宽度下 1:1；窄屏只按 360 断点微调，不缩放字体 |
| RP-03 | **颜色原值** | 使用 4.2 的 HEX/RGBA 原值，不近似、不替换 |
| RP-04 | **字体原值** | 字号、字重、行高按 4.3 表；系统字体栈；不引入商用字体 |
| RP-05 | **组件一致** | 同一视觉元素只实现一次，页面只组合组件 |
| RP-06 | **交互一致** | 点击反馈、弹层、Toast、轮播、倒计时按 4.6/8 章 |
| RP-07 | **多端一致** | 视觉一致优先；平台差异仅限状态栏/安全区/权限/支付/登录 |

> **状态栏换算**：设计稿状态栏为 30px。真机实现时，页面 `padding-top: 30px` 替换为 `statusBarHeight`；吸顶栏 `top: 30px` 替换为 `statusBarHeight`；详情页导航 `top: 40px` 替换为 `statusBarHeight + 10px`；底部固定栏 `bottom: 0` 需叠加 `env(safe-area-inset-bottom)`。不得硬编码 30/40。

### 5.2 底部 TabBar

#### 5.2.1 视觉规格（Figma 原值）

#### 5.2.2 实现方案

**推荐：5 个 Tab 页面 + 原生 tabBar 隐藏 + 自定义 `ni-tab-bar` 组件。**

| 步骤 | 说明 |
| --- | --- |
| pages.json | 配置 `tabBar`（5 个 pagePath、占位 icon、文字），保证 `uni.switchTab` 可用 |
| 隐藏原生 | 每个 Tab 页 `onShow` 调用 `uni.hideTabBar({ animation: false })`；微信小程序同样适用 |
| 自定义栏 | 每个 Tab 页底部引入 `<ni-tab-bar :active="'home'" />`，`position: fixed` |
| 切换 | `uni.switchTab({ url })`；发布按钮 `uni.navigateTo('/pages/publish/index')` |
| 状态 | 各 Tab 页保持自己的页面栈与滚动位置；TabBar 只负责导航与未读数 |
| 深链 | `uni.switchTab` 不支持参数；需要携带参数时先 `switchTab`，再用全局 store/事件传递 |

> **为什么不使用单页 + 组件切换**：Figma 的 5 个 Tab 是完整页面，单页方案会失去页面生命周期、返回栈和分享落地能力。uni-app x 不支持 tabBar `midbutton`，因此采用“隐藏原生 + 自定义栏”是改动最小、全端一致的方案。
>
> **微信小程序注意**：`uni.hideTabBar` 后原生占位消失，自定义栏固定底部；页面需设置 `padding-bottom: 92px + safe-area`。若审核要求使用原生 TabBar，可降级为原生 5 Tab + 悬浮发布按钮（视觉与 Figma 有差异，需设计确认）。

### 6.2 分层与依赖

```
pages → composables → services → api → request
              ↘ stores ↗
models / utils / config 可被所有层引用
```

| 规则 | 说明 |
| --- | --- |
| 禁止反向依赖 | `api` 不得引用 `services`；`services` 不得引用 `pages` |
| Store 可被 services 与 pages 引用 | Store 不直接发请求，统一走 service |
| 页面不直接调用 `uni.request` | 必须经过 `request.ts` |
| 平台差异收敛 | `utils/platform.ts` + 条件编译；页面不写平台判断 |
| 组件无业务 | `ni-*` 基础组件不依赖 store；业务组件可接收数据与事件 |
| 类型集中 | 所有接口/模型类型放 `models/`，禁止页面内重复定义 |

### 6.3 状态管理（Pinia）

| Store | 核心状态 | 主要动作 | 持久化 |
| --- | --- | --- | --- |
| `user.store` | token、refreshToken、profile、authStatus、community、unread | login/logout/refreshProfile/updateCommunity | token + profile（加密） |
| `app.store` | theme、elderMode、config、network、safeArea、statusBarHeight | loadConfig/setTheme/toggleElder | settings |
| `item.store` | homeFeed、nearbyFeed、zoneFeeds、filters、myItems、detailCache | fetchHome/fetchNearby/fetchZone/toggleFavorite | homeFeed 10min |
| `order.store` | ordersByType、currentOrder、payingOrder | fetchOrders/fetchDetail/createOrder/updateStatus | 不缓存金额 |
| `social.store` | conversations、unreadByConv、friends、requests | fetchConversations/fetchFriends/markRead | 会话列表 |
| `life.store` | posts、categories、detail、likes | fetchPosts/fetchDetail/toggleLike | 10min |
| `service.store` | requests、offers、filters | fetchServices/respond | 10min |
| `community.store` | current、bindings、nearby、applied | fetchMine/searchNearby/apply | current |
| `notification.store` | list、unread、filter | fetch/read/readAll | 列表缓存 |

**原则**：

- 单一数据源：跨页面共享状态放 Store；页面私有状态用 `ref/reactive`；
- 服务端为准：物品、订单、钱包余额等交易状态不做长期缓存；
- 事件驱动：WebSocket 下行事件由 `App.uvue` 接收后分发到 Store；
- 乐观更新仅限收藏/点赞；支付、验货、放款不做乐观更新。

### 6.4 网络层

```ts
// api/request.ts 关键约定
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
  traceId: string;
}

interface RequestOptions {
  url: string;
  method?: 'GET' | 'POST' | 'PUT' | 'DELETE';
  data?: Record<string, any>;
  headers?: Record<string, string>;
  idempotent?: boolean; // 写操作默认 true
  loading?: boolean;
  timeout?: number; // 默认 15000
}
```

| 能力 | 规则 |
| --- | --- |
| BaseURL | `config/env.ts`：dev/test/staging/prod |
| 认证 | `Authorization: Bearer <accessToken>`；`X-Refresh-Token` 续期 |
| 幂等 | 写操作自动生成 `X-Idempotency-Key`（UUID v4），同一业务动作复用 |
| 统一响应 | `code === 0` 成功；否则抛 `ApiError` |
| 错误码 | 40001/40101/40301/40302/40901/42201/42901/50000 统一映射到用户文案 |
| 40101 | 静默续期一次；失败跳登录并记录回跳 |
| 40302 | 弹认证引导（实名/业主） |
| 40901 | 提示“物品已被预约”，刷新详情 |
| 42901 | 提示限流，按钮冷却 |
| 重试 | GET 幂等重试 1 次（网络错误/5xx）；写操作不自动重试 |
| 取消 | 页面 `onUnload` 取消未完成请求 |
| 日志 | 记录 method/path/status/耗时/traceId；不打印 token/手机号/身份证 |
| Mock | `config/env.mock=true` 时走本地 fixture；接口契约以 OpenAPI 为准 |

#### 9.1.3 认证状态机

```
NOT_LOGIN → LOGGED_IN_UNVERIFIED → VERIFYING → VERIFIED_UNOWNER

VERIFIED_UNOWNER → SUBMITTING_PROOF → PENDING_AUDIT → VERIFIED_OWNER
                                        │
                                    REJECTED(可重提，3次转人工)
VERIFIED_OWNER ⇄ FROZEN（违规冻结，在售物品自动下架）
```

### 10.3 WebSocket

```json
// 上行
{ "action": "MSG_SEND", "payload": { "clientMsgId": "u1", "conversationId": "c1", "type": "TEXT", "content": "你好" } }
{ "action": "MSG_ACK", "payload": { "clientMsgId": "u1" } }
{ "action": "MSG_READ", "payload": { "conversationId": "c1", "lastMsgSeq": 1024 } }
{ "action": "PING", "payload": { "ts": 1731300000000 } }

// 下行
{ "action": "MSG_PUSH", "payload": { "seq": 1025, "message": { "...": "ChatMessage" } } }
{ "action": "ORDER_EVENT", "payload": { "orderId": "o1", "event": "STATUS_CHANGED", "status": "ESCROWED" } }
{ "action": "AUDIT_EVENT", "payload": { "itemId": "i1", "step": 2, "result": "PROCESSING" } }
{ "action": "PONG", "payload": { "ts": 1731300000000 } }
```

| 规则 | 说明 |
| --- | --- |
| 心跳 | 30s PING；连续 2 次无 PONG 判定断线 |
| 重连 | 1/2/4/8…60s 指数退避 |
| 增量 | 重连后按会话 `lastSeq` 拉取 |
| 降级 | WS 不可用 → HTTP 发送 + 30s 轮询 + 推送 |
| 分发 | `App.uvue` 统一接收，写入 Store；页面不直连 |

## 11. 非功能设计

### 11.1 性能

| 指标 | 目标 | 手段 |
| --- | --- | --- |
| 首页首屏（4G） | ≤ 2s | 分包、SWR 缓存、骨架屏、关键请求并行、图片 CDN |
| 详情首屏 | ≤ 2.5s | 首图优先、轮播懒加载、留言/推荐延迟 |
| 列表滚动 | ≥ 55fps（目标 60fps） | `list-view` 复用、图片定尺寸、避免长列表 blur |
| 列表翻页 | ≤ 500ms | 预取下一页、分页 20 |
| 包体积 | 微信主包 ≤ 2MB，总包 ≤ 20MB | 分包、CDN、按需注入 |
| 启动 | 冷启动可交互 ≤ 2s | 并行配置/刷新 Token、缓存首屏 |
| AI 质检 | ≤ 60s | 服务端流水线 + 进度推送 |
| 图片 | 缩略图 ≤ 1s，原图 ≤ 3s | WebP、CDN 裁剪、渐进加载 |

**Vapor 性能注意事项**：

- 性能测试必须打 release 包；debug 模式性能较差；
- 长列表用 `list-view` + `list-item`；`v-for` 必须有 `:key`；`list-item` 与 `list-view` 同文件；
- 避免在长列表使用 `backdrop-filter`、大阴影、径向渐变；
- `view/text/image` 可使用 `flatten` 拍平；不要滥用；
- 图片 `lazy-load`；首屏图 eager；
- `swiper` 默认高度 150px，首页喇叭站卡片需显式高度 132px；
- 避免频繁 `setData` 式全量更新；用响应式局部更新。

### 11.2 安全与隐私

| 类别 | 措施 |
| --- | --- |
| 传输 | 全站 HTTPS；Token 放 Header；敏感字段额外加密 |
| 本地 | Token/用户信息加密存储；身份证/姓名不落盘；手机号脱敏展示 |
| 支付 | 幂等键；结果双通道确认；不做乐观更新；防重复拉起；回调验签（服务端） |
| 权限 | 相机/相册/定位/通知使用时申请；拒绝有引导；隐私政策首启弹窗 |
| 内容 | UGC 端侧正则提示 + 服务端内容安全（A-09）；生活频道/服务互助/留言/私信全覆盖 |
| 账号 | 注销入口；注销后数据匿名化；异常登录提醒 |
| 日志 | 不打印 token/手机号/身份证/支付参数；traceId 全链路 |
| 分享 | 分享卡片不包含详细门牌号；默认仅小区公共见面点 |

### 11.3 无障碍与长辈模式

| 编号 | 要求 | 实现 |
| --- | --- | --- |
| AB-01 | 触控热区 ≥ 44×44 | 视觉尺寸可小，透明热区补足；按钮/图标/列表项 |
| AB-02 | 对比度 ≥ 4.5:1 | 正文/按钮；6–9px 文案需设计复核 |
| AB-03 | 不只靠颜色 | 交易方式同时有图标 + 文字；状态有文案 |
| AB-04 | 屏幕阅读器 | 图标按钮提供 `aria-label`/无障碍文案；图片 alt |
| AB-05 | 字号缩放 | 跟随系统字号；长辈模式 +2px、按钮 +8px |
| AB-06 | 减弱动效 | 关闭非必要动画；保留状态反馈 |
| AB-07 | 键盘/辅助 | 图片轮播提供左右按钮；弹层可关闭 |

> **设计风险**：Figma 中大量 6–9px 文案（认证徽标、时间、地址）低于常见可读阈值。默认按设计实现，同时提供长辈模式；建议设计评审将最小字号提升至 10px（见 13.2 R-01）。

### 11.4 深色模式

- Figma 未提供深色稿；本期**只交付浅色模式**，不自行发明深色配色；
- Token 架构预留：所有颜色走 SCSS 变量/语义 Token，禁止页面硬编码；
- `manifest.json` 暂不开启 `darkmode`；Web/小程序如需跟随宿主，需设计补稿后再开；
- 后续接入方式：`theme.json` + `@media (prefers-color-scheme: dark)` 或 `uni.onThemeChange`；参考 UI 规范第 8 章映射。
